# 特性系统设计（sim/traits）

> 状态：**接口已定稿并接入引擎**；231 个特性全部为 no-op 占位（`implemented=False`），
> 具体 handler 逐个实现中。本文档是评审与实现的依据。

## 0.5 已确认的设计决策（2026-08-18 评审）

1. **未建模机制（第 7 节的 12 项）全部不做**，依赖它们的特性（标 ⚠）一律暂缓，
   先实现不依赖新机制的 ~150 个，机制后续逐步补齐。
2. **事件广播到场下精灵**：确认可行。积累类特性（搜刮/地脉/散热等）依赖此语义。
3. **特性战斗中不显示**：`state` 序列化不包含任何特性字段（双方都看不到）。
   被训练的模型若要查询精灵特性，自行查 `data/spirits.json` / `data/traits.json`，
   不依赖对战提供。`trait_id` 仅引擎内部使用。
4. **迸发类型已扩展**（burst.py）：`attack_power_flat`（原有）、`attack_power_percent`、
   `skill_use_count`（使用次数+1）、`energy_cost_flat`（本次能耗-）、
   `enemy_energy_cost`（攻击后敌方能耗+）。消耗时机仍为"入场后首次行动"。
5. **特性效果不写入日志**：handler 不向 `state.log` 追加任何文字（与"特性不可见"一致），
   效果只通过 state 变化体现（buff/能量/血量/魔力等均可从 state 观测）。
   `ctx.log` 保留在接口中，但默认不使用。
6. **特性 buff 打来源标记**：特性带来的增强复用 buff 系统，但 `Buff.source_kind="trait"`，
   `Buff.is_gain()/is_loss()` 判定时特性来源不算普通"增益/减益"（萌芽印记/王子诺言等
   "获得增益"类效果不会把特性 buff 算进去）。
7. **百分比速度**：buff 系统新增 `speed_percent` 类型（每层 +10%），
   `buffs.get_speed_value` 在固定值基础上乘百分比；客户端显示同步支持。

## 0. 一句话概括

每个精灵携带一个特性（来自 `spirits.json` 的 `feature.id`，数据在 `data/traits.json`）。
引擎在关键时机**广播事件**给所有精灵的特性 handler（handler 自己判断相关性），
在数值计算处**查询修正**（属性/威力/能耗/速度/连击/吸血等增量）。
特性按 `trait_id` 注册，未实现的是空实现，不产生任何效果、不打印日志。

## 1. 数据与挂载

| 位置 | 内容 |
| --- | --- |
| `data/traits.json` | 231 个特性：`{id, name, desc, spiritIds}`（描述为自然语言，是实现的唯一依据） |
| `spirits.json` | 每只精灵 `feature: {id, desc}`，596 只全部有特性 |
| `BattlePet.trait_id` | 精灵当前特性的 id；由 `make_battle_pet` 从 spirit 数据挂载 |
| `BattlePet.trait_state` | 该特性的战斗内状态（次数/累计值/开关），跨回合保留 |
| `evolution.rebind` | 进化 / 首领化 / 萌化后按新形态重新绑定特性并清空状态 |

序列化：**不包含特性**（战斗中不显示，双方都看不到）。AI 查询特性自行查
`data/spirits.json`（feature.id）与 `data/traits.json`（id/name/desc）。

## 2. 接口骨架

```
sim/traits/
  base.py       TraitContext（上下文）+ TraitHandler（基类，所有钩子默认空实现）
  registry.py   注册表：trait_id -> handler；默认把 traits.json 全部注册为 no-op
  __init__.py   emit / emit_lethal / query_* / rebind / ensure_entry / report
  impl/         具体 handler 实现包（目前为空，按分类分文件）
```

## 3. 事件钩子（引擎调用 `traits.emit(state, "事件名", scope=..., ...)`）

**scope**：`all`（双方全部，含场下，默认）/ `side`（单方全部）/ `active`（双方在场）/ `self`（单个）。
默认广播到全部精灵（含场下），handler 用 `ctx.side / ctx.subject / ctx.active` 判断是否与自己相关——
这是"入场前积累类"特性（搜刮/地脉/散热等，场下也要听到事件）的必要设计。

| 事件 | 触发时机 | ctx 关键字段 | 典型特性 |
| --- | --- | --- | --- |
| `turn_start` | 回合开始（双方行动已选定） | action_a/b | 预警、先知、哨兵、盲拧 |
| `entry` | 入场：首发/主动换人/力竭替换/脱离换人 | subject=入场精灵 | 渴求、图书守卫者、蓄电池 |
| `leave` | 离场：主动换人/脱离（不含力竭） | subject=离场精灵, extra.incoming | 快充、洁癖、木桶戏法 |
| `charge` | 聚能 | energy_gain | 长久保存制法 |
| `energy_gain` | 获得能量（聚能/印记/技能等） | energy_gain | 腐植循环、系统发育、草木苏醒时 |
| `skill_start` | 技能开始（扣能耗后、效果前） | skill, energy_cost, is_first | 变形活画、月牙雪糕 |
| `attack` | 造成伤害后 | damage, target, hit_count | 灰色肖像、与星星同行 |
| `take_damage` | 受到伤害后 | damage, subject | 刺肤、坚韧铠甲、扎手、诅咒 |
| `lethal` | 致命伤害判定（伤害应用前，返回 True 免死） | damage, subject | 不死鸟、化茧 |
| `kill` | 击败敌方 | subject=被击败者, target=击杀者 | 恶魔的晚宴、振奋虫心 |
| `faint` | 力竭（魔力扣除后） | subject | 诈死、虚假宝箱、付给恶魔的赎价 |
| `counter` | 应对成功强制先手 | is_counter | 斗技、圣火骑士、思维之盾、威慑 |
| `defense` | 使用防御技能 | skill | 奔波命 |
| `status_skill` | 使用状态技能 | skill | 泛音列 |
| `skill_end` | 技能结束（含离场结算后） | skill, damage_dealt, hit_count | 氧循环、助燃、浸润、生物碱 |
| `round_end` | 回合结束（主客场顺序广播，可重复触发） | - | 生长、养分重吸收、毒蘑菇、花精灵 |
| `buff_gain` | 获得增益/减益（接入点：buffs.add_buff 调用处，待接入） | extra.buff_type/value | 营养液泡、王子的诺言 |
| `dot_damage` | 属性伤害结算（接入点：buffs.py 各 _apply_*，待接入） | subject | 仁心、耐活王 |
| `heal` | 回复生命 | heal, extra.base_heal | 戏耍（把回复转为敌方扣血） |
| `weather_change` | 天气变化（接入点：weather.set/clear，待接入） | weather | 得寸进尺、流沙统治者、冰雪魂魄 |
| `revive` | 复活（力竭后复活） | subject | 不朽 |

## 4. 修正钩子（引擎调用 `traits.query_*`，计算时汇总）

**查询对象**：默认只查"被查询精灵自身"的特性（绝大多数是自身效果）；
仅 `query_energy_cost` 与 `query_hit_count` 额外查询敌方在场精灵的特性
（冰封"在场时敌方全技能能耗+1"、无差别过滤"全场连击固定"等光环）。
ctx 约定：`ctx.target`=被查询精灵（自身效果用 `ctx.target is ctx.actor` 判定），
`ctx.subject`=另一方（敌方/攻击方）。
所有修正一律"增量"语义：返回 0 表示无修正；乘数 = 1.0 + 增量之和。

| 查询 | 返回 | 语义 | 典型特性 |
| --- | --- | --- | --- |
| `query_stat_multiplier` | float | 属性百分比增量（0.2=+20%） | 囤积、壮胆、悲悯、守护之心 |
| `query_power` | (percent, flat) | 技能威力增量 | 目空、顺风、冰钻、月光审判 |
| `query_energy_cost` | int | 技能能耗增量 | 缩壳、冰封、浸润 |
| `query_speed` | int | 速度增量 | 流沙统治者、变形活画 |
| `query_damage_dealt` | float | 造成伤害乘数增量 | 绒粉星光、天通地明 |
| `query_damage_taken` | float | 受到伤害乘数增量 | 偏振、绝对秩序、逐魂鸟 |
| `query_hit_count` | (flat, percent, forced) | 连击增量 + 强制固定值 | 乘风连击、侵蚀；无差别过滤(固定2) |
| `query_lifesteal` | float | 吸血比例增量 | 滴眼液、盛宴 |
| `query_energy_limit` | int | 能量上限增量 | 多人宿舍 |
| `query_energy_gain` | int | 获得能量增量 | （预留） |
| `query_energy_shortfall` | int | 能量不足兜底（handler 自行付代价） | 石头大餐、盛宴 |
| `query_heal` | int | 回复量增量 | 戏耍、盛宴 |
| `query_skill_usable` | bool | 技能可用性强制（None=不干预） | 正位宝剑、宝剑王牌 |
| `query_skill_element` | int | 技能属性改写 | 展翅（普通系→翼系） |

另有 `modify_round_end_repeats` / `modify_poison_repeats` 用于"回合结束效果额外触发"类（双向光速/复方汤剂）。

## 8. 实现流程建议

1. 按上表分组，**一批一批实现**；**不依赖新机制的 ~150 个优先**，⚠ 的（第 7 节机制）全部缓后。
2. 每个 handler：**人工阅读该特性描述** → 判定语义/触发时机/作用对象 → 手写
   `class Xxx(TraitHandler)` 覆写钩子 → `register(Xxx())`，置 `implemented=True`。
   描述是唯一依据，不用关键词匹配。
3. 一批完成后跑冒烟对战验证；`traits.report()` 可随时查看进度。
4. 规则争议（某个特性的语义）记入该特性的 docstring，便于复核。
